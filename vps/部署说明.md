# VPS 集中部署说明（腾讯云轻量 · Ubuntu）

把 AI 服务装到你的腾讯云 VPS 上，团队成员只需在插件里填一次「服务地址 + 团队口令」即可使用。
以后你改 AI 逻辑/话术，只更新这台 VPS，全团队立刻生效，他们什么都不用做。

- 你的公网 IP：`106.54.206.174`
- 端口：`3210`
- 安全：用「团队口令」防止别人盗用你的额度。第一版走 HTTP（不加密传输），
  内部小团队可接受；以后想加 HTTPS 再绑域名升级。

---

## 一、把服务装到 VPS（推荐 git 方式，以后能一键更新）

仓库是公开的，VPS 直接从 GitHub 拉代码，**不需要任何账号密码**。

1. 腾讯云控制台 → 轻量应用服务器 → 你的实例 → 点「**登录**」，打开网页版终端。
2. 在终端里依次运行（每行回车）：

   ```bash
   cd ~
   sudo apt-get update -y && sudo apt-get install -y git
   git clone https://github.com/vickyldr/kol-extension.git kol-repo
   cd kol-repo
   bash vps/setup.sh
   ```

   > 仓库根就是代码根（`bilingual-extension/` 子目录是旧结构残留，已空，别 cd 进去）。
   > 装好后服务由 systemd 托管为 `kol-assistant.service`（见第五节），日常更新只用 `git pull origin main` + `systemctl restart`。

3. 按提示依次填：
   - **阿里云百炼 API Key**；
   - **团队口令**：每个同事插件里都填这个；
   - **管理员口令**：只有你自己填，用来编辑/删除话术（要和团队口令不同）。
   脚本会自动装 Node、把服务注册成 systemd 服务 `kol-assistant`（开机自启 + 崩溃自动拉起）、并做本机自检。

> 以后**更新服务端 = 标准三步**（不用传 zip、不用重填 Key，话术也不会丢）：
> ```bash
> cd /home/ubuntu/kol-repo && git pull origin main && sudo systemctl restart kol-assistant
> curl -s localhost:3210/health   # 看到 ok:true 就成功
> ```
> 详见第五节。**千万别手动 `nohup node server.js`**——会和 systemd 进程抢 3210 端口（`EADDRINUSE`）、用错数据目录。

## 二、放行端口（最容易漏的一步）

腾讯云轻量自带防火墙，默认**不开** 3210 端口，不放行同事就连不上：

1. 控制台 → 轻量应用服务器 → 你的实例 → 「**防火墙**」标签。
2. 「添加规则」：应用类型自定义，协议 **TCP**，端口 **3210**，来源 `0.0.0.0/0`，确定。

## 三、验证

浏览器直接打开：`http://106.54.206.174:3210/health`
能看到一段 `{"ok":true,...}` 的文字，就说明外网通了。

## 四、团队成员怎么用

每位同事在插件里：

1. 打开侧边栏 → 顶部「**⚙️ 服务器设置**」。
2. 服务地址填：`http://106.54.206.174:3210`
3. 团队口令填：你设置的那个团队口令。
4. 管理员口令：**同事留空**（普通成员只能新增和查看）。
5. 点「保存并连接」，右上角显示「千问已连接」即可。

**你自己（管理员）**：服务地址、团队口令照填，外加在「管理员口令」里填你设的那个管理员口令——
填了之后，话术库里每条话术下面才会出现「编辑 / 删除」按钮。

> 本机自己单人用（不连 VPS）：服务地址保持 `http://127.0.0.1:3210`，口令全部留空即可。

## 五、日常维护与更新

> ⚠️ **服务由 systemd 托管（`kol-assistant.service`），千万别再手动 `nohup node server.js`**——
> systemd 进程一直占着 3210，你手动起的会撞 `EADDRINUSE`，而且数据目录会跑偏。一切走 systemctl。
> 仓库在 **`/home/ubuntu/kol-repo/`**（`bilingual-extension/` 子目录是旧结构残留，已空，别在那里操作）；
> git 走 SSH（已配置，不用 token），remote 是 `git@github.com:vickyldr/kol-extension.git`。

**重要：你的话术库和产品资料存在独立目录 `~/kol-data`，更新代码不会动它们。**

- **更新服务端**（最常见，标准三步，记住这个）：
  ```bash
  cd /home/ubuntu/kol-repo
  git pull origin main                  # main 是发布分支；SSH 已配，直接拉
  sudo systemctl restart kol-assistant  # systemd 重启，自动用配置的用户和数据目录
  curl -s localhost:3210/health         # 看到 ok:true 就成功
  ```
  不用传 zip、不用重填 Key，话术库也不会丢，团队无需任何操作即生效。
- **查状态 / 看日志**：
  ```bash
  sudo systemctl status kol-assistant --no-pager
  sudo journalctl -u kol-assistant -n 50 --no-pager   # 不是 ~/kol.log（那是历史手动启动留下的）
  ```
- **改 Key 或口令**：在 `/etc/systemd/system/kol-assistant.service.d/model.conf` 等覆盖文件里改环境变量，
  然后 `sudo systemctl daemon-reload && sudo systemctl restart kol-assistant`（数据保留）。
- **排查端口被占 / 多个杂进程**：`sudo lsof -i :3210`；务必只留 systemd 那一个 node 进程。
- **备份话术库**：`~/kol-data/scenario-archive.json`，或在插件「话术库 → 导出备份」。

## 六、红人资源库 + 进度看板（独立服务 kol-roster · 端口 3220）

同一台 VPS 上还跑着一个**独立**的管理端只读网页服务（红人资源库 + 进度看板），
代码在 `apps/roster/`，systemd 服务名 **`kol-roster`**，端口 **3220**，和上面的 `kol-assistant`（3210）**完全分开**。

- **更新它**（和主后端一样三步，只是换服务名 + 端口）：
  ```bash
  cd /home/ubuntu/kol-repo
  git pull origin main
  sudo systemctl restart kol-roster
  curl -s localhost:3220/health         # 看到 ok:true 就成功
  ```
- **首次部署 / systemd 配置 / 访问地址 / 口令保护**：见 `apps/roster/部署.md`（逐步全在那）。
- **别混**：改主插件后端 `server.js` 就 restart `kol-assistant`；改 `apps/roster/server.js` 就 restart `kol-roster`，
  health 看对应端口（3210 / 3220）。
