## 0. 一句话

在**现有 KOL 插件**之外，新建**两个只读为主的管理端网页**：
- 🗂️ **红人资源库**：合作过的红人的永久档案（身份/合同/价格/平台/脚本/主题/效果/值不值得/黑名单/性格），给管理层浏览、搜索、筛选、复盘。
- 📊 **进度看板**：在合作的实时状态（待回复/未读/待办/阶段），表格 + 看板，看「谁卡在哪」。

两者**不进现有插件**，放本仓库 `apps/roster/`，共用一个零依赖 Node 后端，读 VPS 上插件已经产出的数据。

---

## 1. 三端架构（最重要，别搞混谁产数据谁读数据）

```
现有插件（运营/实习生在 IG 现场用，照旧）
   │  已经在推 BACKUP_KEYS 到
   ▼
VPS  ~/kol-data/backups/<每个人 insid>.json     ← 实习生侧数据源（每人一个文件）
VPS  ~/kol-data/roster-overrides.json           ← 领导侧数据（本工具网页写，新建）
VPS  ~/kol-data/roster-team.json                 ← insId→实习生名字 小映射表（新建，你/领导维护一次）
   │  读 + 合并
   ▼
apps/roster/server.js（零依赖 Node，新进程，新端口）
   ├─ /  →  🗂️ 红人资源库页
   └─ /board →  📊 进度看板页
```

- **实习生数据**：单向从插件流上来（插件 → `/api/backup` → `backups/<insid>.json`）。本工具**只读**它。
- **领导数据**（仅「优质」标记一项）：本工具网页**可写**，只落 `roster-overrides.json`，**绝不回写实习生备份**（回写也会被插件下次同步覆盖，且违反根 CLAUDE.md 红线5）。
- 展示 = 实习生数据 + 领导覆盖，**读时合并**。两条流各写各的、各有归属，不打架。
- 「领导改了实习生能不能看到」= 二期可选：把领导覆盖也下发给插件展示（要插件改动）。**一期不做**，先记着。

## 2. 数据源：备份里实际有什么（来自插件 `BACKUP_KEYS`，真实字段）

> 来源：`sidepanel.js` `BACKUP_KEYS`，结构见 `kol-reminder.js` / `reminders.js`。

### `kolProfiles`（红人档案，按规范化名字 key 存）—— 资源库主力
`displayName` 展示名 · `appid` App User ID · `legalname` 法定名称 · `email` · `payment` 付款方式 · `notes` 备注 · `updatedAt`
**本工具要让插件新增**：`script` 脚本 · `theme` 主题 · `temperament` 性格备注（脾气/会不会脱稿）

### `kolThreads`（红人会话状态，按名字 key 存）—— 进度看板主力 + 群名解析源
`threadId` IG 数字 ID（深链） · `title`/`creatorName` 名字或**群名** · `avatarUrl` 真实头像 · `isGroup` · `lastMsgFrom`/`lastMsgPreview` 最新消息 · `needsReplyRaw`+`needsReplyReason` 待不待回复 · `unread` · `isOnline` · `firstUnrepliedAt`/`lastCreatorMessageAt` 计时锚点 · `judge` 截止判断 · `lastSeenAt`

### `kolTodos`（待办，数组）—— 进度看板
`id` · `text` · `dueAt` 到点时间 · `threadId` 关联红人 · `done` · `dismissed`

### `kolSummaries`（对话真总结，名字 key + 数字 threadId 双写）—— 两边都用
`text` 一句话中文总结 · `name` · `tid` · `key` · `updatedAt`

### 其余（资源库基本用不上）
`kolReminderSettings`（身份：本人 insid + 负责产品） · `kolProactiveLang` · `kolThreadsSchema` · `kolQuickReplies`（个人私有，不进库）
**本工具要让插件新增进备份**：`kolUnderstanding`（`/api/analyze` 算出的「当前阶段」，给进度看板用）

## 3. 群聊名称解析（价格 / 平台 / 授权期限）—— 用 AI 抽，不用正则

### 真实样本（注意：格式不统一）
```
�janyourdiary_ 250$ igttfcb 1mon...
```
**群名没有统一格式**：分隔符可能是空格 / 横杠 / 逗号，平台写法**完全个人喜好**（`igttfcb`、`IG+TT`、`ins抖音`…都可能）。
→ 所以**不写固定正则**，规则化解析必然漏。**用 AI（qwen-flash）抽结构化字段**最稳。

### 做法
1. 取 `isGroup` 会话的 `title`（私聊名是人名，不抽）。
2. 喂给后端一个轻量 prompt，让 AI 返回 JSON：
   ```json
   { "price": "250", "currency": "USD", "platforms": ["Instagram","TikTok","Facebook"], "usagePeriod": "1个月" }
   ```
   prompt 里约束：只抽群名里**明确写了的**，**不编造**（红线2）；认不出的平台代码尽量翻译，实在不懂就原样保留。
3. **价格走快路**：`$\d+` / `\d+\$` 这种好认的先用正则秒取，认不出再交给 AI；平台/期限一律 AI。
4. **缓存**：按群名原文签名存结果（如 `rosterNameParseCache`），**群名没变不重算**（仿插件 `kolUnderstanding` 的缓存思路，省 token）。

### 注意
- 群名 handle 与 `kolProfiles` 的 key（displayName 归一）**可能对不齐**，匹配时 handle 也参与 `profileKey()` 归一后比对；对不上就单独成条并标「未关联档案」。
- AI 抽取在**本工具后端**做（`apps/roster/server.js` 调百炼），不依赖插件。

## 4. 字段总表（每个字段：来源 / 谁填 / 哪填 / 存哪）

| 字段 | 来源 | 谁填 | 在哪填 | 落盘 |
|---|---|---|---|---|
| 名字 / 头像 | 自动 | — | — | backups（kolProfiles/kolThreads） |
| App User ID / 法定名称 / 邮箱 / 付款方式 | 手填 | 实习生 | 插件档案卡 | backups（kolProfiles） |
| 价格 / 发布平台 / 授权期限 | 解析群名 | — | — | 实时算（源 kolThreads.title） |
| 脚本 / 主题 | 手填 | 实习生 | 插件档案卡（新增字段） | backups（kolProfiles） |
| 性格备注（脾气/脱稿） | 手填 | 实习生 | 插件档案卡（新增字段） | backups（kolProfiles） |
| 沟通总结 | 自动 | — | — | backups（kolSummaries） |
| **值得合作（勾选）+ 推荐理由** | 手填 | **实习生** | 插件档案卡（新增字段） | backups（kolProfiles） |
| **黑名单（开关 + 原因）** | 手填 | **实习生** | 插件档案卡（新增字段） | backups（kolProfiles） |
| **优质（标记，领导回看的核心）** | 手填 | **领导** | 资源库网页 | roster-overrides.json |
| 对接号（我方身份） | 自动 | — | — | backups 文件名 = insid |
| 阶段（洽谈/报价/发布/付款） | 自动 | — | — | backups（kolUnderstanding）+ 兜底推断 |

字段取值建议：
- 值得合作（实习生）：**勾选**（值不值）+ **推荐理由**文本（为什么推荐）。
- 黑名单（实习生）：`是/否` + 原因（放鸽子/虚高/脱稿严重…）。
- 优质（领导）：**勾选标记**（优质 / 未标记）。领导回看实习生的「值得合作 + 推荐理由」后，给红人盖「优质」章。需要时可扩成 优质/一般 两档。

工作流：实习生在前线打勾「值得合作」+ 写推荐理由 → 领导网页回看 → 标「优质」。

## 5. 合并去重 + 我方身份 + insId→名字 小表

### 红人按名字合并（一对多）
- 主键 = `profileKey(名字)`（搬插件逻辑：trim + 折叠空格 + 小写）。
- 多个实习生 / 多个 insid 接过同一红人 → 合并成一条，**对接记录做成列表**：`[{insId, 实习生名字, lastSeenAt}]`。
- 合作记录（不同时间不同价格/平台）也是列表摞起来，按时间排。

### 我方身份 = 备份文件名（免费）
- 读 `backups/<insid>.json`，里面所有红人/待办**天生属于这个 insid** → 读取时打标，无需任何人手填。

### `roster-team.json`（新建，一次性维护）
```json
{ "insid_aaa": "小王", "insid_bbb": "小王", "insid_ccc": "小美" }
```
- 解决「一个人 2 个 ins 号」：把多个 insid 映射到同一实习生名。
- 看板就能显示「小王（2 个号）」而不是两串陌生 id。
- 谁维护：你 / 领导，手改这个 JSON 或网页加个小表单（二期）。

## 6. 进度看板：阶段来源（两个都做）

1. **真阶段**：让插件把 `kolUnderstanding`（`/api/analyze` 的「当前阶段」）加进 `BACKUP_KEYS` → 同步上来直接用。
2. **兜底推断**：没分析过的红人，按规则粗估阶段：
   - 有总结含「报价/价格」→ 已报价；有待办含「发布/上线」→ 待发布；群名解析出价格 → 至少「已谈价」；其余 → 洽谈中。
   - 规则简单透明，标「推断」与真阶段区分。

看板列（草案）：`洽谈中 → 已报价 → 待发布 → 待付款 → 已完成`。每张卡：头像 + 名字 + 待回复/未读标 + 最近总结 + 到点待办 + 对接号。

## 7. 两个网页长什么样（文字草图）

### 🗂️ 红人资源库（`/`）
- 顶部：搜索框 + 筛选条（平台 / 价格区间 / 值得合作 / 黑名单 / 对接人）。
- 主体：红人卡片/表格列表。每条：头像 名字 平台标 价格 值得合作标 黑名单标。
- 点开：详情抽屉 —— 身份 + 合同 + 合作记录列表（价格/平台/期限/脚本/主题/效果）+ 性格备注 + 沟通总结时间线 + 对接历史。
- 领导编辑口：详情里「效果 / 值得合作 / 黑名单」三项可改（其余只读）。

### 📊 进度看板（`/board`）
- 切换：看板视图（按阶段分列）/ 表格视图（可排序）。
- 表格列：名字 阶段 待回复? 未读? 最近总结 下一个待办+到点 对接号 在线?。
- 红/橙高亮：待回复、今天到点。
- 「打开对话」深链：有 `threadId` 跳 IG 对话，没有退收件箱（搬插件兜底逻辑）。

## 8. 后端接口（`apps/roster/server.js`，零依赖）

只读为主，少量写（领导字段 + team 表）。

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/roster` | GET | 合并所有 backups + overrides，返回红人资源库列表 |
| `/api/roster/:key` | GET | 单个红人详情（合作记录/对接历史/总结时间线） |
| `/api/roster/:key/leader` | POST | 领导写：优质标记 → roster-overrides.json |
| `/api/board` | GET | 合并 threads + todos + understanding，返回进度看板数据 |
| `/api/team` | GET/POST | insId→名字 映射读写（roster-team.json） |
| `/health` | GET | 存活检查 |

- 权限：整站一个口令保护（复用插件 `KOL_ASSISTANT_TOKEN` 思路）；领导写接口再加管理员口令（复用 `X-KOL-Admin` 思路）。
- 数据目录复用插件的 `KOL_DATA_DIR`（同一台 VPS、同一份 `~/kol-data/`）。
