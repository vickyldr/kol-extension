## 0. 一句话

在**现有 KOL 插件**之外，新建**两个只读为主的管理端网页**：
- 🗂️ **红人资源库**：合作过的红人的永久档案（身份/合同/价格/平台/脚本/主题/效果/值不值得/黑名单/性格），给管理层浏览、搜索、筛选、复盘。
- 📊 **进度看板**：在合作的实时状态（待回复/未读/待办/阶段），表格 + 看板，看「谁卡在哪」。

两者**不进现有插件**，放本仓库 `apps/roster/`，共用一个零依赖 Node 后端，读 VPS 上插件已经产出的数据。

## 1. 三端架构（最重要，别搞混谁产数据谁读数据）

```
现有插件（运营/实习生在 IG 现场用，照旧）
   │  已经在推 BACKUP_KEYS 到
   ▼
VPS  ~/kol-data/backups/<每个人 insid>.json     ← 实习生侧数据源（每人一个文件）
VPS  ~/kol-data/roster-overrides.json           ← 领导侧数据（本工具网页写，新建）
VPS  ~/kol-data/roster-team.json                 ← insId→实习生名字 小映射表（新建，你/领导维护一次）
   │  读 + 合并
   ▼
apps/roster/server.js（零依赖 Node，新进程，新端口）
   ├─ /  →  🗂️ 红人资源库页
   └─ /board →  📊 进度看板页
```

- **实习生数据**：单向从插件流上来（插件 → `/api/backup` → `backups/<insid>.json`）。本工具**只读**它。
- **领导数据**（仅「优质」标记一项）：本工具网页**可写**，只落 `roster-overrides.json`，**绝不回写实习生备份**（回写也会被插件下次同步覆盖，且违反根 CLAUDE.md 红线5）。
- 展示 = 实习生数据 + 领导覆盖，**读时合并**。两条流各写各的、各有归属，不打架。
- 「领导改了实习生能不能看到」= 二期可选：把领导覆盖也下发给插件展示（要插件改动）。**一期不做**，先记着。

## 2. 数据源：备份里实际有什么（来自插件 `BACKUP_KEYS`，真实字段）

> 来源：`sidepanel.js` `BACKUP_KEYS`，结构见 `kol-reminder.js` / `reminders.js`。

### `kolProfiles`（红人档案，按规范化名字 key 存）—— 资源库主力
`displayName` 展示名 · `appid` App User ID · `legalname` 法定名称 · `email` · `payment` 付款方式 · `notes` 备注 · `updatedAt`
**本工具要让插件新增**：`script` 脚本 · `theme` 主题 · `temperament` 性格备注（脾气/会不会脱稿）

### `kolThreads`（红人会话状态，按名字 key 存）—— 进度看板主力 + 群名解析源
`threadId` IG 数字 ID（深链） · `title`/`creatorName` 名字或**群名** · `avatarUrl` 真实头像 · `isGroup` · `lastMsgFrom`/`lastMsgPreview` 最新消息 · `needsReplyRaw`+`needsReplyReason` 待不待回复 · `unread` · `isOnline` · `firstUnrepliedAt`/`lastCreatorMessageAt` 计时锚点 · `judge` 截止判断 · `lastSeenAt`

### `kolTodos`（待办，数组）—— 进度看板
`id` · `text` · `dueAt` 到点时间 · `threadId` 关联红人 · `done` · `dismissed`

### `kolSummaries`（对话真总结，名字 key + 数字 threadId 双写）—— 两边都用
`text` 一句话中文总结 · `name` · `tid` · `key` · `updatedAt`

### 其余（资源库基本用不上）
`kolReminderSettings`（身份：本人 insid + 负责产品） · `kolProactiveLang` · `kolThreadsSchema` · `kolQuickReplies`（个人私有，不进库）
**本工具要让插件新增进备份**：`kolUnderstanding`（`/api/analyze` 算出的「当前阶段」，给进度看板用）

## 3. 群聊名称解析（价格 / 平台 / 授权期限）—— 用 AI 抽，不用正则

### 真实样本（注意：格式不统一）
```
�janyourdiary_ 250$ igttfcb 1mon...
```
**群名没有统一格式**：分隔符可能是空格 / 横杠 / 逗号，平台写法**完全个人喜好**（`igttfcb`、`IG+TT`、`ins抖音`…都可能）。
→ 所以**不写固定正则**，规则化解析必然漏。**用 AI（qwen-flash）抽结构化字段**最稳。

### 做法
1. 取 `isGroup` 会话的 `title`（私聊名是人名，不抽）。
2. 喂给后端一个轻量 prompt，让 AI 返回 JSON：
   ```json
   { "price": "250", "currency": "USD", "platforms": ["Instagram","TikTok","Facebook"], "usagePeriod": "1个月" }
   ```
   prompt 里约束：只抽群名里**明确写了的**，**不编造**（红线2）；认不出的平台代码尽量翻译，实在不懂就原样保留。
3. **价格走快路**：`$\d+` / `\d+\$` 这种好认的先用正则秒取，认不出再交给 AI；平台/期限一律 AI。
4. **缓存**：按群名原文签名存结果（如 `rosterNameParseCache`），**群名没变不重算**（仿插件 `kolUnderstanding` 的缓存思路，省 token）。

### 注意
- 群名 handle 与 `kolProfiles` 的 key（displayName 归一）**可能对不齐**，匹配时 handle 也参与 `profileKey()` 归一后比对；对不上就单独成条并标「未关联档案」。
- AI 抽取在**本工具后端**做（`apps/roster/server.js` 调百炼），不依赖插件。

字段取值建议：
- 值得合作（实习生）：**勾选**（值不值）+ **推荐理由**文本（为什么推荐）。
- 黑名单（实习生）：`是/否` + 原因（放鸽子/虚高/脱稿严重…）。
- 优质（领导）：**勾选标记**（优质 / 未标记）。领导回看实习生的「值得合作 + 推荐理由」后盖「优质」章。需要时可扩 优质/一般 两档。
- 红人类型：口播 / 街采 / 宝妈（可扩）。
- 阶段：洽谈中 / 已报价 / 制作中 / 已完成 / 终止。

工作流：实习生在前线打勾「值得合作」+ 写推荐理由 → 领导网页回看 → 标「优质」。

### 「最近跟进时间」定义（核心，别搞错）
- = **实习生上次回复该红人的时间**，不是红人发消息的时间（红人动态**不计**）。
- 插件在「检测到整段精读最后一条是我发的 / 我方发出新消息」时，给该 thread 盖 `lastFollowUpAt` 时间戳（蹭现有 `lastIsMine`/`myReplyAfter` 判定，改动很小）。
- 看板用 `now - lastFollowUpAt` 算「多久没跟进」：🟢近 🟡几天 🔴超 7 天。越久越红越靠上。
- 用途：① 抓「很久没人跟进」的红人；② 按对接人聚合，看哪个实习生滞后（飞书「自动更新时间」的用法，但更自动）。

## 5. 合并去重 + 我方身份 + insId→名字 小表

### 红人按名字合并（一对多）
- 主键 = `profileKey(名字)`（搬插件逻辑：trim + 折叠空格 + 小写）。
- 多个实习生 / 多个 insid 接过同一红人 → 合并成一条，**对接记录做成列表**：`[{insId, 实习生名字, lastSeenAt}]`。
- 合作记录（不同时间不同价格/平台）也是列表摞起来，按时间排。

### 我方身份 = 备份文件名（免费）
- 读 `backups/<insid>.json`，里面所有红人/待办**天生属于这个 insid** → 读取时打标，无需任何人手填。

### `roster-team.json`（新建，一次性维护）
```json
{ "insid_aaa": "小王", "insid_bbb": "小王", "insid_ccc": "小美" }
```
- 解决「一个人 2 个 ins 号」：把多个 insid 映射到同一实习生名。
- 看板就能显示「小王（2 个号）」而不是两串陌生 id。
- 谁维护：你 / 领导，手改这个 JSON 或网页加个小表单（二期）。

## 6. 进度看板：阶段来源（两个都做）

1. **真阶段**：让插件把 `kolUnderstanding`（`/api/analyze` 的「当前阶段」）加进 `BACKUP_KEYS` → 同步上来直接用。
2. **兜底推断**：没分析过的红人，按规则粗估阶段：
   - 有总结含「报价/价格」→ 已报价；有待办含「发布/上线」→ 待发布；群名解析出价格 → 至少「已谈价」；其余 → 洽谈中。
   - 规则简单透明，标「推断」与真阶段区分。

看板阶段（定稿）：`洽谈中 → 已报价 → 制作中 → 已完成 / 终止`。

### 6b. 现实约束：只有「当前」，没有历史
- AI 只扫**当前对话**，**没有历史进度沉淀**（没做那层输入）。所以看板是**当前快照**，不是历史管线。
- **阶段** = AI 看最新聊天判断的**当前状态**，随对话实时变，**不记流转**。
- **漏斗删掉「已完成」**：没历史，数不准完成数；只留能从当前聊天抓到的（洽谈/报价/制作/终止）。

### 6c. 「今日盯人」逻辑（实习生跟进，最终版）
- **不看回复快慢、不用天数刻度**——实习生天天上班，标准是**当天清完待回复**。
- 只数**漏人**：`红人发了消息（needsReplyRaw）且对接人还没回`。**隔夜没回 = 失责**（红标）。
- 数据：插件已有 `needsReplyRaw` + `firstUnrepliedAt`（第一次没回的时间戳），「隔夜」直接能算。
- **区分**：红人自己不回（鸽）≠ 实习生失责——那是「我方已回、对方不理」，不计进盯人。
- 顶部预警 = 「N 个待回复隔夜没回」+ 名字；每个实习生一行 = 「在聊 X · 漏 Y（Z 个隔夜）」。

### 6d. 提醒小窗 vs 进度看板：分开，但数据打通
- **分开**：提醒 = 输入/当下/个人（跟着操作员、自动弹、轻量、可操作）；进度 = 输出/大盘/全队（网页、只读、监控）。形态与受众不同，合并会互相拖累。
- **打通**：两边读**同一份底层数据**（kolThreads / 待办 / `lastFollowUpAt` / `needsReplyRaw`），口径一致。看板「打开对话」深链跳回 IG/插件，闭环。
- 看板可给「只看我的 + 待催」视图（加强版回顾），但实时行动仍靠小窗弹。

## 7. 两个网页长什么样（已有样机 `apps/roster/mockup/`）

> 两个页面同一套干净列表风格（蓝白管理后台风），不照抄飞书密表。
> 样机文件：`mockup/library.html`（资源库）、`mockup/board.html`（看板），浏览器可直接开。

### 🗂️ 红人资源库（`/`）—— 复盘视角「还值不值得再合作」
- 顶部：搜索框 + 数字条（总数 / 已合作 / ⭐优质 / 值得 / 黑名单）+ 筛选条（优质 / 值得 / 黑名单 / 类型 / 地区 / 价格 / 对接人）。
- 列表列：外号·handle / 地区 / 类型 / 价格·平台 / 主题 / **值得合作（实习生勾+理由）** / **⭐优质（领导标）** / 黑名单 / 对接人。
- 点行 → 右侧详情抽屉：身份（App ID/法定名称/邮箱/付款）+ **历次合作记录**（每次价格/平台/期限/脚本/主题）+ 性格备注 + 沟通总结时间线 + 历任对接人。
- 领导编辑口：仅「⭐优质」可改，其余只读。

### 📊 进度看板（`/board`）—— 跟进视角「谁卡住、谁没人管」
- 顶部三块：① **整体进度漏斗**（洽谈→报价→制作→完成→终止 各几条）；② **🔴跟进预警**（X 个红人 >7天没人跟进，列名字）；③ **实习生跟进情况**（按回复频率：勤/一般/滞后）。
- 主列表：外号·handle / 地区 / 类型 / 价格·平台 / 主题 / 阶段 / **最近跟进（核心，颜色+相对时间）** / 对接人 / 备注。默认按进度分组、按「最近跟进」排序（越久没回复越靠上）。
- 视图切换：列表 / 卡片 / 按负责人。
- 「打开对话」深链：有 `threadId` 跳 IG 对话，没有退收件箱（搬插件兜底逻辑）。

## 8. 后端接口（`apps/roster/server.js`，零依赖）

只读为主，少量写（领导字段 + team 表）。

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/roster` | GET | 合并所有 backups + overrides，返回红人资源库列表 |

| `/health` | GET | 存活检查 |

- 权限：整站一个口令保护（复用插件 `KOL_ASSISTANT_TOKEN` 思路）；领导写接口再加管理员口令（复用 `X-KOL-Admin` 思路）。

## 13. 实现笔记（v1 已上线，server.js 真实行为）

**产品缩写（写进代码，从 ins id 认产品）：**
`vivavideo=VA  aicatch=AC  rythmix=RM  vivacut=VC  recco=RC  wisemeal=WM`
- ins id 含某产品名 → 该红人归该产品（`aicatch_vip2` → AC）。一个红人可属多产品。
- 两个网页都有「总表 + 各产品 tab」按此过滤。

**备份文件结构**：`{ userId, data:{ kolProfiles, kolThreads, ... }, updatedAt }` —— 真实 BACKUP_KEYS 在 `.data` 里（别当顶层读）。

**显示名 / handle**：
- 显示名优先级：档案外号 > 私聊档案名 > 清洗后的群名 > 兜底。
- `cleanGroupName` 砍掉群名里「价格/币种/条款」那串、去掉开头 emoji 乱码；`stripProductPrefix` 去掉 `AC `/`VA ` 这类产品前缀 → 得到 IG handle。
- 列表显示「外号 @handle」，没外号时显示「@handle」或清洗名。

**当前阶段**：优先用插件 AI 真阶段 `kolUnderstanding[key].stage`；没有就 `computeStage` 关键词启发式推断（黑名单/鸽→终止；发布→已完成；脚本/制作→制作中；报价/币种→已报价；否则洽谈中）。看板按阶段分组。

**字段调整（v0.28.1）**：删「脚本」（与主题重复，留**主题/方向**）、删「性格备注」（并进**推荐理由**）。

**地区**：`detectRegion` 看语言/币种 —— 韩文/韩/KRW→KR；假名/日本/JPY→JP；其余→TW。

**今日盯人**：红人发了消息没回（`needsReplyRaw`）= 漏人；`firstUnrepliedAt` 超 1 天 = 隔夜失责；黑名单不算。

**「当前在聊什么」**：默认单行截断，点击展开全文（保留换行）；表格 `overflow-x:auto` 小屏横向滚不撑爆。

**唯一身份 = IG handle（关键，别用外号判同一性）**：
- 同 handle = 同一红人 → 合并成一条（不同外号、跨产品群聊、历史+群聊都合）；挂多产品、多对接人、多来源；不同外号收进 `aliases` 别名。
- **绝不用外号判同一性**：不同产品可能给不同人起同名（撞名），按外号并会错并不同人。
- 没 handle 的记录（只有外号）：不合并，标 `noId`「⚠无ID待核对」，靠人工。
- 实现：`mergeByHandle` 只在 **buildLibrary** 做（资源库一人一行）；**buildBoard 不合并**（看板按群聊粒度，同一人多个群=多行待办，各自对接人/产品/状态），靠 `nickIndex` 给看板行补统一外号。

**主观评价不抹平（值得/黑名单/备注）**：同一人在不同对接人/产品手里表现可能不同。合并时**按来源分别保留**进 `evaluations`（每条带 by=对接人、products、值得+理由、黑名单+原因、备注）。既有人说值得又有人拉黑 → `conflict=true`，资源库标「⚠评价分歧」，详情按对接人列出，**领导看完分歧再定优质**（优质是人维度的领导一锤定音）。

**历史导入**：`appendImport` 把 `roster-import.json`（live 覆盖或 `seed/`）转成 person 记录追加，再由 `mergeByHandle` 统一按 handle 和群聊去重合并。导入文件由 xlsx 解析生成（handle 主键去重 + 收 aliases + 标 noId）。资源库行显示来源标（💬群聊/📚历史/💬+📚）+ 别名 + 无ID；筛选「红人类型/语言地区」按数据动态生成。
