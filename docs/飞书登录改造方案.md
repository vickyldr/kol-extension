# 飞书 OAuth 登录改造方案（KOL 双语沟通助手插件）

> 目的：把插件现在的「填团队口令才能用」换成「用飞书账号登录才能用」。
> 只有小影 / 影趣飞书通讯录里的员工，登录后才能使用插件。
> 本文给对接的技术同学（陈少奇）看，说明要做什么、谁做哪块、开工前要敲定什么。

---

## 1. 现状 & 目标

- **现状**：插件用一个静态「团队口令」（后端 `KOL_ASSISTANT_TOKEN`，请求头 `X-KOL-Token`）鉴权，全team共用一个口令。
- **目标**：删掉团队口令，改成**飞书 OAuth 单点登录**。用户打开插件 → 点「用飞书登录」→ 飞书授权 → 登录成功才能用。
- **好处**：
  - 同事不用记口令，点一下就进；
  - 权限跟着飞书通讯录走，**离职自动失效**；
  - 可审计（谁在用一目了然），比共用口令安全得多。

---

## 2. 登录流程（跑通后的样子）

**用户视角**：打开插件 → 点「用飞书登录」→ 跳出飞书授权页 → 点同意 → 回到插件，显示「已登录：张三」，开始用。

**技术流程**：
1. 插件打开后端的授权入口，后端带 `app_id` + 回调地址重定向到飞书授权页。
2. 用户在飞书点「同意」，飞书带一个 `code` 回调到**后端**。
3. 后端用 `code` 换 `user_access_token`，拿到用户身份（姓名 / 邮箱 / 企业 / 部门）。
4. 后端校验该用户**属于小影 / 影趣企业** → 通过则**签发一个会话凭证**（带过期时间）。
5. 插件保存该凭证，以后每次调 `/api/*` 都带上它（替换现在的 `X-KOL-Token`）。
6. 后端每个 `/api/*` 校验凭证有效且未过期；过期就让用户重新登录。

> 说明：走「后端主导」的 OAuth（回调落在后端域名）比在扩展里直接跑更干净、`app_secret` 不下发到前端，更安全。

---

## 3. 要改三块 + 分工

### A. 飞书开放平台注册应用 —— 公司侧（陈少奇 / 飞书管理员）
- 建一个「网页应用 / 企业自建应用」；
- 拿到 **`app_id`** / **`app_secret`** 给后端；
- 配置**重定向 URL（回调）**：`https://kol-assistant.lianquapp.com/api/auth/feishu/callback`（域名以实际后端为准）；
- 开通权限：获取用户基本信息（如通讯录 `contact:user.base`、`authen` 登录相关 scope）；
- 明确**可登录范围**（哪个/哪些企业、是否限部门）。

### B. 后端 `server.js` —— 代码可协作，部署在公司后端
- **新增接口**：
  - `GET /api/auth/feishu/start`：生成 `state` 防伪，重定向到飞书授权页；
  - `GET /api/auth/feishu/callback`：收 `code` → 换 token → 校验企业 → 签发会话凭证 → 回给插件；
  - `GET /api/auth/me`（可选）：校验凭证、返回当前登录用户，供前端显示「已登录：XX」。
- **鉴权改造**：把现在校验 `KOL_ASSISTANT_TOKEN` 的中间件，改成校验会话凭证（`/health` 继续放行）。
- **密钥**：`app_secret` 放**环境变量**，绝不进 git（红线）。会话凭证建议用**签名 JWT**（无状态、后端不用存库）。
- **管理员权限**：现在的 `X-KOL-Admin`（改/删话术、删物料、导入团队库）逻辑保留，或升级成「按飞书部门/指定人判断是不是管理员」。

### C. 插件前端 —— Vicky 侧（本地 Claude 协助）
- 「⚙️ 服务器设置」里：**删掉「团队口令」输入框**，换成**「用飞书登录」按钮** + 显示当前登录人；
- 走 OAuth：用 `chrome.identity.launchWebAuthFlow`（扩展标准做法）或打开后端授权入口，拿回会话凭证；
- 把凭证存 `chrome.storage.local`，替换现在的 `kolConfig.token`；
- 所有请求头改带会话凭证；凭证过期 → 提示重新登录；
- 登录后可**自动带出飞书用户名 / 部门**，少让同事手填一项（比如 ins id / 产品可预填）。

## 4. 开工前要陈少奇 / 秦小芬确认（这几个不定，代码没法动）

1. **小影 和 影趣 是同一个飞书企业，还是两个？**（决定配一个应用还是两个、怎么判断"是不是自己人"）
2. **飞书应用谁注册、谁给 `app_id` / `app_secret`？**
3. **回调域名**用 `kol-assistant.lianquapp.com` 对吗？（要在飞书应用里加白名单）
4. **可登录范围**：两家**全员**，还是限某些部门？
5. **管理员**（能改话术库 / 删物料的人）怎么认——指定飞书某几个人 / 某部门？

---

## 5. 工作量 & 风险

- **工作量**：中等。后端 OAuth 接口 + 前端登录按钮，联调顺利约几天。
- **风险 / 注意**：
  - **别一刀切**：切换时先做**灰度**——后端同时支持「团队口令 or 飞书登录」，稳定后再删口令，避免把现有用户挡在门外。
  - **`app_secret` 绝不进 git**，只放环境变量（后端红线）。
  - **回调 URL 少配一个就登录失败**：飞书应用白名单里必须有那个 callback 地址。
  - 插件是 Chrome 商店分发的，改了鉴权要 `manifest` 版本 +1、重新打包上架。

---

## 6. 建议推进顺序

1. 敲定第 4 节 5 个问题；
2. 陈少奇建飞书应用、给 `app_id/secret` + 配回调；
3. 后端加 OAuth 接口（可先测试环境）；
4. 插件加「用飞书登录」按钮，联调；
5. 灰度：口令与飞书登录并存 → 验证通过 → 去掉口令 → 插件发新版。
